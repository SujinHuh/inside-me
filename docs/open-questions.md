# Inside Me 미결정 질문

이 문서는 개발을 시작하기 전에 답이 필요한 질문과 프로토타입을 사용한 뒤 결정할 질문을 분리한다. 사용자가 답하면 관련 질문을 `답변됨`으로 바꾸고 `requirements.md`와 `decisions.md`에 반영한다.

## 상태 정의

- `답변 필요`: 구현 방향을 크게 바꾸므로 개발 전에 답이 필요함
- `기본안으로 진행 가능`: 권고 기본안으로 프로토타입을 만든 뒤 바꿀 수 있음
- `프로토타입 후 검증`: 실제 사용 경험을 보고 결정하는 편이 나음
- `답변됨`: 결정 로그에 반영됨

## 먼저 답이 필요한 질문

### Q-015 — “두 가지 버전”의 의미

- 상태: 답변됨 → DEC-011
- 영향: 화면 흐름과 개발 범위
- 답변: 한 앱 안에 자유 음성 기록, 글 기록, AI 턴 대화의 세 가지 경험을 둔다.
- 후속 확인: 자유 기록이 끝난 뒤 AI 질문으로 전환되는 정확한 방식은 프로토타입 설계 때 확인한다.

### Q-001 — 실제로 사용할 기기와 운영체제

- 상태: 답변됨 → DEC-012
- 영향: 앱 형태, 알림, 마이크 권한, 배포와 테스트 방법
- 답변: 안드로이드폰을 주로 사용하고 컴퓨터도 사용한다. 아이폰은 사용하지 않는다.
- 이유: 음성과 취침 전 알림은 모바일 운영체제의 제약을 크게 받으므로 기술 스택보다 실제 사용 기기를 먼저 알아야 한다.

### Q-002 — AI의 답변을 듣는 방식

- 상태: 답변됨 → DEC-013
- 영향: 음성 합성, 비용, 응답 지연, 화면 구성
- 답변: AI의 공감 표현과 질문도 목소리로 듣고 싶다. 구체적인 재생 방식은 직접 사용한 뒤 AI의 추천을 받아 결정한다.
- 운영 기본안: AI 질문은 음성과 글을 동시에 제공하고 언제든 음소거할 수 있게 한다.

### Q-003 — 한 턴의 녹음 조작 방식

- 상태: 답변됨 → DEC-015
- 영향: 음성 UI, 발화 종료 감지, 오전사 수정, 접근성
- 질문 의도: 사용자가 버튼을 눌러 녹음을 시작하고 다시 눌러 끝낼지, 앱이 침묵을 감지해 자동으로 한 턴을 끝낼지를 묻는 질문이다.
- 답변: 버튼을 한 번 눌러 시작하고 다시 눌러 종료하는 권고안을 수용했다. 감정을 정리하는 중간 침묵을 발화 종료로 오해할 수 있으므로 첫 MVP에서는 자동 종료하지 않는다.

### Q-004 — 기록 저장 위치와 동기화

- 상태: 답변됨 → DEC-014
- 영향: 개인정보, 백엔드, 로그인, 기기 분실 시 복구
- 답변: 나중에는 다른 기기에서도 이어서 보고 싶지만 첫 버전은 현재 기기에만 저장한다. 기록 동기화 서버는 지금 만들지 않는다.
- 운영 기본안: 내보내기와 삭제를 지원하고 AI 처리에 필요한 최소 텍스트만 외부로 전송한다.

### Q-005 — 원본 음성 보관

- 상태: 답변됨 → DEC-016
- 영향: 개인정보, 저장 공간, 재생 기능, 전사 재처리
- 답변: 목소리를 다시 들을 필요가 없으므로 원본 음성은 전사와 분석에 사용한 뒤 삭제한다. 텍스트와 감정 결과만 저장한다.

### Q-006 — 한 번의 감정 탐색 길이

- 상태: 답변됨 → DEC-017
- 영향: 질문 수, 비용, 취침 전 피로, 완료율
- 답변: 약 5분 안에 핵심 질문 3~6개를 진행하고 사용자가 원하면 더 이어가는 권고안을 수용했다.

### Q-007 — 하루 기록 개수

- 상태: 답변됨 → DEC-018
- 영향: 데이터 모델, 달력의 대표 표정, 알림 완료 처리
- 답변: MVP에서는 하루의 내용을 한 기록으로 묶어 정리한다. 사건별로 나누어 저장하는 기능은 나중에 확장한다.

## 프로토타입을 본 뒤 결정할 질문

### Q-008 — 월간 달력의 표정이 나타낼 정보

- 상태: 프로토타입 후 검증
- 영향: 아이콘 체계와 하루의 복합 감정 표현
- 질문: 달력에서 얼굴 하나를 봤을 때 가장 먼저 기억하고 싶은 것은 대표 감정, 기분의 편안함 정도, 감정의 강도 중 무엇인가?
- 현재 고려사항: 얼굴 하나로 하루를 단순화하지 않도록 상세 화면에서는 복수 감정을 유지한다.

### Q-009 — 이전 기록을 AI가 기억하는 범위

- 상태: 프로토타입 후 검증
- 영향: 개인화, 비용, 프라이버시, 잘못된 패턴 단정
- 질문: AI가 이전 일기를 참고해 반복되는 감정과 욕구를 연결해 주길 원하는가? 원한다면 어느 기간까지 참고하는 것이 편안한가?
- 현재 고려사항: 첫 MVP에서는 현재 기록에 집중하고, 과거 패턴은 사용자가 요청할 때만 불러오는 방식이 안전하다.

### Q-010 — 감정을 돌보는 제안의 깊이

- 상태: 프로토타입 후 검증
- 영향: AI 안전 기준, 콘텐츠 범위, 질문 길이
- 질문: 감정을 찾은 뒤 가장 받고 싶은 도움은 어떤 형태인가? 실제로 도움이 되었던 방식이 있다면 무엇인가?
- 현재 고려사항: 먼저 이해, 진정, 표현, 요청, 경계, 휴식 중 현재 목적을 물은 뒤 작은 행동 하나를 제안한다.

### Q-011 — 알림의 말투와 미루기

- 상태: 프로토타입 후 검증
- 영향: 지속 사용, 부담감, 취침 전 경험
- 질문: 밤 알림이 어떤 말투로 오면 부담 없이 열어볼 수 있을까? 놓친 날에는 다시 알려주기를 원하는가?
- 현재 고려사항: 연속 기록을 압박하지 않고 미루기와 오늘 건너뛰기를 허용한다.

## 구현 전 반드시 별도 설계할 안전 질문

### Q-012 — 위기 상황에서의 동작

- 상태: 답변 필요 — 외부 배포 차단
- 영향: 사용자의 즉각적 안전과 제품 책임
- 질문: 심각한 자해·자살·타해 위험이 드러날 때 앱이 감정 탐색을 멈추고 도움 연결을 안내하는 것에 동의하는가?
- 현재 고려사항: 외부 사용자에게 배포하기 전 지역에 맞는 안내와 전문가 검토가 필요하다.

### Q-016 — AI의 감정 후보 제시 방식

- 상태: 프로토타입 후 검증
- 영향: 사용자의 자기결정권, 선택 피로와 탐색 속도
- 질문: AI가 근거와 함께 감정 후보를 몇 개 제시하고 사용자가 고르는 방식이 실제로 편안한가?
- 현재 고려사항: 진단·단정 금지는 안전 원칙으로 유지하고 후보 3~5개 제안 방식은 도그푸딩으로 검증한다. 관련 결정은 DEC-003이다.

### Q-017 — 제품 로그 문서 형식 확정

- 상태: 답변 필요
- 영향: 장기 문서 관리와 추적성
- 질문: 현재 사용 중인 `requirements.md`, `product-log.md`, `decisions.md`, `open-questions.md` 분리 방식을 공식 운영 형식으로 확정할 것인가?
- 현재 고려사항: 로깅 자체는 REQ-011로 확정되었고, 문서 분리 형식은 DEC-008에 임시 운영으로 남긴다.

### Q-013 — AI 및 음성 처리 서비스

- 상태: 기본안으로 진행 가능
- 영향: 구현 비용, 한국어 품질, 지연, 데이터 보존 정책
- 질문: 이미 선호하거나 사용할 수 있는 AI·음성 API가 있는가? 월간 사용 비용과 외부 전송에 대해 허용 가능한 기준은 무엇인가?
- 현재 고려사항: 실제 기기와 개인정보 결정을 먼저 한 다음 서비스를 비교한다.

### Q-014 — 이전 음성 인식이 불명확했던 표현

- 상태: 답변 필요
- 영향: 누락된 핵심 요구사항 가능성
- 질문: 앞선 발화의 “완전히 시드 완전 10초”는 어떤 의미였는가?
- 이유: 의미를 추측해 요구사항으로 확정하지 않기 위해 원문 상태로 남겨 두었다.

## 기술과 시각 방향에서 답할 질문

### Q-018 — MVP 기술 스택 확정

- 상태: 답변됨 → DEC-021, DEC-022, DEC-025
- 영향: 프로젝트 생성, 폴더 구조, 실행·테스트 명령과 이번 주 구현 속도
- 답변: `TypeScript + React Native + Expo + Expo Router`와 MSA가 아닌 모듈형 모놀리스 방향을 사용자가 수용했다.

### Q-019 — 시각 방향과 참고 화면

- 상태: 참고자료 수신, 프로토타입 후 검증
- 영향: 디자인 토큰, 컴포넌트 구조, 아이콘과 폰트 선택
- 질문: 참고 화면을 가져온 뒤 “부드러운 XP/90년대 개인용 다이어리 + 현대적 가독성” 방향과 더 절제된 현대 방향을 작은 목업으로 비교해도 되는가?
- 현재 고려사항: Windows Classic 계산기 이미지를 참고자료로 받았다. 각진 창, 입체 버튼, 회색 표면과 파란 제목 표시줄의 촉감을 차용하되 픽셀 복제는 하지 않는다. 관련 결정은 DEC-026, 해석은 `docs/references/windows-classic-ui.md`에 있다.

### Q-020 — 이번 주 MVP의 성공선

- 상태: 답변됨 → DEC-029, DEC-030
- 영향: 일주일 구현 범위와 검증 기기
- 답변: Android Expo Go에서 핵심 흐름을 먼저 만들고 안정되면 내부 APK로 전환한다. 컴퓨터 웹과 PWA는 같은 코드베이스의 다음 확장 단계로 둔다.

### Q-021 — Hallmark 프로젝트 스킬 설치 여부

- 상태: 기본안으로 진행 가능
- 영향: UI 작업 때 불러오는 외부 지침의 재현성과 유지보수
- 질문: UI 구현을 시작할 때 Hallmark를 `.codex/skills/hallmark/`에 프로젝트 범위로 설치할 것인가?
- 현재 고려사항: 지금은 공식 원본을 검토해 Inside Me용 참고 문서와 `AGENTS.md`에 적용했다. 설치하지 않아도 이 원칙은 지킬 수 있으며, 외부 코드와 다수의 상세 규칙을 프로젝트에 들이기 전에 실제 필요성을 확인하는 편이 안전하다.

### Q-022 — 클라이언트와 서버 폴더 구조 확정

- 상태: 답변 필요
- 영향: 프로젝트 스캐폴딩과 API 키 보안
- 질문: 별도 `frontend/`, `backend/` 프로젝트를 지금 만들지 않고, 하나의 Expo 프로젝트 안에서 `app/`, `src/features/`, `src/core/`, `src/infrastructure/`, 선택적 `server/` 경계로 시작할 것인가?
- 현재 고려사항: 외부 AI 비밀 키가 필요할 때만 얇은 서버 라우트를 추가하고, 서버가 실제로 커질 때 별도 앱으로 추출하는 방식을 권고한다. 관련 제안은 DEC-027이다.

### Q-023 — 첫 구현 세로 흐름 확정

- 상태: 답변됨 → DEC-028
- 영향: 이번 주 도그푸딩 시작 시점과 첫 화면 범위
- 답변: 먼저 `앱 열기 → 글로 하루 이야기 입력 → AI 또는 임시 탐색기가 감정 후보 제시 → 사용자가 확인 → 폰에 저장 → 달력 날짜를 눌러 다시 보기`까지 작동시킨 뒤 같은 흐름에 음성을 붙인다. 문서에는 “세로 흐름”이라는 이름만 쓰지 않고 이 행동과 결과를 함께 기록한다.

### Q-024 — 첫 Android 실행·설치 방식

- 상태: 답변됨 → DEC-029, DEC-030
- 영향: 이번 주 시작 속도, 개발 컴퓨터 의존과 폰 설치 경험
- 답변: Expo Go QR 코드로 Android 개발을 시작하고 핵심 흐름이 안정되면 내부 APK로 전환한다. PWA도 같은 코드베이스의 후속 범위에 포함한다.
