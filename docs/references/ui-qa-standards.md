# Inside Me UI QA 근거·적용 기준

- 상태: UI QA 외부 근거와 프로젝트 판정 기준의 단일 참고
- 작성일: 2026-08-26
- 공식 문서 검토일: 2026-08-26
- 관련 요구사항: REQ-001, REQ-021, REQ-026, REQ-028, REQ-029
- 관련 결정: DEC-055(DEC-064로 대체), DEC-060, DEC-061, DEC-064

## 문서 역할

외부 표준·플랫폼 최소 기준과 Inside Me의 제품 성공 기준을 구분한다. 외부 기준을 임의로 Inside Me 사용성 통과로 확대하지 않고, 프로젝트 기준을 WCAG·Android의 공식 수치처럼 표현하지 않는다.

## Inside Me 제품 성공 기준

다음은 외부 표준의 수치가 아니라 사용자가 확정한 제품 목적을 검증하기 위한 프로젝트 판정 기준이다.

### `감정일기를 쓰도록 돕는다`

- 글·음성·AI 턴 대화 입력은 모두 사용자가 자신의 감정·욕구를 읽고 비교·선택·확정하여 기록하는 공통 흐름으로 이어져야 한다.
- AI 설명이 없어도 사용자가 어휘를 직접 읽고 자신에게 가까운 표현을 찾을 수 있어야 한다.
- 감정·욕구 선택은 새로운 설문이 아니라, 사용자가 먼저 쓴 이야기를 구체적인 언어로 돌아보게 돕는 기록 과정이어야 한다.

### `읽어보면서 한눈에 들어온다`

`271개`를 한 뷰포트에 작은 글씨로 모두 압축한다는 뜻이 아니다. 총 271개는 충족 감정 70개·미충족 감정 91개·욕구 110개다. `한눈에`는 첫 휴대폰 화면에서 세 마음 방과 욕구 8개 영역 미리보기를 보고 시작 지점, 단계 탐색과 전체 목록으로 이어지는 방법을 이해하는 것을 뜻한다.

- 첫 화면에서 `충족 감정`, `미충족 감정`, `욕구`의 세 마음 방과 욕구 8개 영역 이름 미리보기를 식별할 수 있다.
- 사용자는 욕구 진입 뒤 도움 없이 `자율성`, `신체적 안녕과 생존`, `연결과 상호의존`, `놀이와 재미`, `삶의 의미`, `진실성과 자기존중`, `아름다움과 평화`, `자기구현과 성장`의 8개 영역 목록에 접근할 수 있다.
- 첫 화면 안내를 본 뒤 추가 설명 없이 원하는 탐색 축을 고르고 실제 감정 또는 욕구 단어를 읽기 시작할 수 있다.
- 현재 방·감정의 결 또는 욕구 영역·선택 상태·전체 목록으로 돌아가는 방법을 탐색 중에도 잊지 않게 표시한다.
- 그룹 제목·여백·색면·텍스트 배치로 단어를 훑어볼 수 있게 하되, 색이나 작은 글자만으로 구조·선택을 구분하지 않는다.
- 271개 전체 어휘는 축약·삭제 없이 단계 탐색·271개 전역 검색·구조화된 전체 목록으로 접근하며, 직접 입력과 `아직 모르겠어요`도 동등한 경로로 남겨둔다. 전역 검색은 현재 방·감정의 결·욕구 영역에 갇히지 않는다.

## 증거 계층과 통과 판정

| 계층 | 증명할 수 있는 것 | 증명할 수 없는 것 | 통과 증거 |
|---|---|---|---|
| 정적·계약 테스트 | 271개 어휘 수, ID·검색·선택·저장 상태 | 배치, 터치 감각, 사용자 이해 | 명령·결과·Git SHA |
| 브라우저 보조 QA | 320·360·412px 배치, 넘침, 경계, 대비, 포커스, 상호작용 | Android 실제 렌더링, 손가락 조작감, 사용자가 구조를 이해했는지 | URL·목업 ID·화면 크기·캡처·측정값·오류 수 |
| 사용자 첫 보기 QA | 설명 없이 세 탐색 축, 욕구 8개 영역의 존재·접근 방법과 시작 방법을 이해·수행했는지 | 다른 사용자의 일반적 성공률 | 화면 버전·질문·사용자 응답·도움 필요 여부·실패 지점 |
| Android 실기기 QA | 키보드·시스템 영역·실제 글꼴·TalkBack·저장·재실행 | 코드 전체 경로의 정적 완전성 | 기기·OS·앱 버전·Git SHA·DV 결과·사용자 응답 |

한 계층의 통과를 다른 계층의 증거로 대체하지 않는다. 핵심 행동에서 도움이 필요했거나, 사용자가 세 탐색 축·욕구 8개 영역의 존재와 접근 경로·선택 상태·전체 목록 접근 방법을 설명하지 못했거나, 고정 UI·시스템 영역이 단어·포커스·다음 행동을 가리면 통과로 표시하지 않는다.

## 갱신 규칙

외부 문서의 발행·갱신일과 검토일을 PR에 남긴다. 공식 승인 수준과 자문 기법을 구분하고, Android·WCAG 기준이 바뀌면 프로젝트 판정에 미치는 영향을 다시 검토한다.
