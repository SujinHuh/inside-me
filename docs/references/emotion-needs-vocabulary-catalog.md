## 정규화와 호환성 원칙

- 원본에서 반복되는 같은 표현은 선택 값 하나로 둔다. 반복 횟수를 사용자의 상태나 강도로 해석하지 않는다.
- `신체적 접촉(스킨십)`은 선택 이름을 `신체적 접촉`으로 두고 `스킨십`을 검색 별칭으로 보존한다.
- 이미지의 괄호 속 설명이 작은 글자로 불명확한 `인생예찬`, `주관을 가짐` 등은 판독 가능한 핵심 표현만 선택 이름으로 보존하고 설명을 임의로 확장하지 않는다.
- 기존 대표 카탈로그의 감정 24개·욕구 16개 ID는 그대로 유지한다. 따라서 이전 로컬 기록의 `emotion-hurt`, `need-rest` 같은 값은 새 카탈로그에서도 같은 뜻을 가리킨다.
- 새 표현 ID는 종류와 정규화된 표시 이름으로 결정하며 화면 정렬 순서에는 의존하지 않는다. 표시 이름을 수정해야 할 때는 기존 ID·검색 별칭·로컬 기록 영향을 먼저 검토한다.

## 화면 적용과 남은 검증

- 기존 한 장 마음 지도는 전체 271개 데이터·검색·복수 선택·직접 추가를 먼저 검증한 구현 이력으로 보존한다. 현재 구현 기준인 C안은 첫 화면에 세 마음 방과 욕구 8개 영역 미리보기를 보여 주고, 방별 단계 탐색·전체 검색·전체 목록으로 같은 정본 카탈로그에 접근한다.
- 색은 영역 구분 보조이며 감정의 좋고 나쁨이나 욕구 충족 여부를 사실로 판정하지 않는다.
- 정적·자동 테스트는 원본 개수와 선택 계약을 확인하지만 Android에서 글자 크기, 긴 버튼, 스크롤 피로와 성능이 적절한지는 `IMP-106`의 `DV-03`으로 확인해야 한다.
