## 이 문서의 목적

다음 개발 대화에서 이전 맥락을 다시 추측하지 않고 바로 작업을 시작하기 위한 인계 문서다. 구현 단계의 이름뿐 아니라 사용자가 실제로 무엇을 하고 무엇을 확인해야 완료인지 기록한다.

실기기 포인터는 `IMP-106` Android 검증 대기다. `IMP-102` 구현과 자동 검증은 완료됐지만 해당 화면의 실제 Android 확인은 `IMP-106`에 포함한다. `DOC-001`과 `IMP-204S`는 완료했고 현재 원격 체크포인트는 실제 AI 사용 조건 사용자 결정이다. `IMP-204C`의 계정·키·외부 전송·과금은 별도 승인 전 시작하지 않는다. 사용자가 기기 확인 가능 상태를 알리면 새 플랫폼 기능보다 `IMP-106`을 먼저 재개한다.

`IMP-204S` 자체는 같은 계약과 테스트 파일에 변경이 집중된 작은 작업이라 주 에이전트가 합성 상황 24개와 순차 실행·요약 도구를 구현하고, 구현 비참여 서브에이전트가 독립 검수했다. 이것은 기존 A·B·C 병렬 개발 운영 방식을 축소하거나 대체하는 결정이 아니다. 다음 작업도 `docs/development-workflow.md`에 따라 공통 계약을 먼저 고정하고, 서로 독립된 소유 경로와 검증 기준을 가진 하위 작업은 기존처럼 병렬 분업한다. 정답 감정·욕구 점수, 새 UI·DB·의존성·실제 공급자 호출은 IMP-204S 범위에 포함하지 않는다.

### 집에서 진행할 Android 누적 실기기 검증 묶음

- 사용자 발화의 `102번 pending`은 현재 실행 원장상 `IMP-106`을 가리킨 것으로 해석한다. `IMP-102` 글 기록·감정 확인·수정 UI 구현은 이미 완료 상태다.
- 저녁에 기능 ID별로 여러 번 QR 실행하지 않는다. 6시 전 병합이 모두 끝난 최신 `origin/main` SHA 하나를 고정하고 `docs/device-validation-checklist.md`의 순서로 한 번의 누적 회귀 검증을 수행한다.
- 실기기 묶음에는 Expo Go 실행, 키보드와 모바일 배치, 사용자 우선 감정·욕구 선택, SQLite 저장·재실행 복원·수정·삭제, 로컬 보조 후보, Android 공유 화면과 접근성을 포함한다.
- IMP-204A/B처럼 앱 화면에 연결되지 않은 순수 비용·예산 로직은 전체 자동 테스트와 독립 검수 결과를 사용하고 폰에서 반복하지 않는다. IMP-204C 실제 공급자 계측, 내부 APK와 외부 배포도 이 묶음에 포함하지 않는다.
- 같은 SHA에서 자동 검증 6개와 필수 실기기 12단계 결과, 기기·OS·실행 시간을 기록해야 IMP-106을 완료로 바꾼다. 검증 중 수정 SHA가 생기면 자동 검증을 다시 실행하고 영향 단계와 저장·재실행·삭제 핵심 흐름을 새 SHA에서 다시 확인한다.

### IMP-204A/B 원격 구현·자동 검증 기록

- 구현: `src/core/ai-costs/`에 가격 조사일과 모델별 단가를 분리한 프로필, 텍스트·자유 음성·턴형 음성·Realtime 음성 비용 순수 계산기와 단일 요청 비용 예약·정산·취소·후속 차단 로직을 추가했다.
- 산식 검증: 한 사람·월 30회 기준 텍스트, 5분 자유 음성, 턴형 음성 핑퐁, Realtime 오디오 기본 비용과 자유 음성 1·3·5·10분을 재현했다. 272K 초과 장문 배수 단가를 적용하고 가격·사용량의 음수·무한대·분수 토큰, 0회 사용과 계산 overflow를 성공값으로 반환하지 않는다.
- 예산 의미: coordinator가 다음 요청의 보수적 예상비를 nano-USD 단위로 올림 예약하고 같은 coordinator에서 한 번에 하나만 허용한다. 실제 비용이 예약액보다 커 승인 목표를 소액 초과하면 이를 표시하고 이후 요청을 막지만, 실제 공급자 과금의 완전한 하드 캡을 보장한다고 표현하지 않는다.

## 1단계 — 첫 기록 전체 흐름

### 사용자가 하는 일

1. Android 폰에서 Inside Me를 연다.
2. 홈 화면에서 `글로 기록하기`를 누른다.
3. 오늘 있었던 일과 현재 기분을 자유롭게 적는다.
4. `감정 살펴보기`를 누른다.
5. 검색·주제별 필터·세로 스크롤로 감정 어휘를 직접 살펴보고 가까운 표현을 먼저 고르거나 직접 추가한다.
6. 욕구 목록도 주제별로 살펴보고 자신에게 중요했던 항목을 먼저 고른다.
7. 잘 모르겠거나 더 살펴보고 싶으면 `AI와 더 살펴보기`를 선택한다. 초기에는 같은 계약을 쓰는 임시 탐색기가 보조 후보와 근거를 보여 줄 수 있다.
8. 자기 선택과 AI 보조 후보를 비교해 최종 감정, 강도와 욕구를 수정·확정한다.
9. 필요한 경우 한 문장 요약을 확인하고 `오늘 기록 저장`을 누른다.
10. 월간 달력의 오늘 날짜에 표정이 나타난다.
11. 오늘 날짜를 눌러 이야기, 감정, 욕구와 요약을 다시 본다.
12. 앱을 닫고 다시 열어도 기록이 남아 있는지 확인한다.
13. 상세 화면에서 자신이 만든 테스트 기록을 수정하고 다시 저장한다.
14. 합성 기록만 있는 테스트 프로필에서 전체 기록을 파일로 내보내고 내보낸 결과가 열리는지 확인한다.
15. 자신이 만든 테스트 기록의 삭제를 확인하고, 앱을 다시 열어도 돌아오지 않는지 확인한다.

- 하루 한 개 기록 저장·수정
- 월간 달력의 대표 표정
- 날짜 상세 조회
- 앱 재시작 후 로컬 기록 복원
- 사용자 확인을 거친 완전 삭제
- 민감정보 안내, 취소·실패 복구와 임시 파일 정리를 포함한 전체 기록 내보내기
- 저장 실패와 빈 입력의 이해 가능한 안내

### 완료 조건

- 사용자가 Android 폰에서 위 15단계를 도움 없이 끝낼 수 있다.
- 같은 날짜에 저장을 반복해 중복 기록이 생기지 않는다.

- AI 도움을 선택하지 않아도 감정·욕구 확인과 저장 흐름을 끝낼 수 있다.

- 웹 저장·삭제·내보내기 검증

### 중요한 제한

- Android 앱과 PWA는 모두 기기 로컬에 기록하므로 자동으로 같은 일기를 공유하지 않는다.
- 기기 간 동기화는 별도의 서버·계정·암호화 결정이 필요한 후속 기능이다.
- PWA 때문에 Android 첫 구현을 늦추지 않되 Android 전용 코드를 공통 핵심에 섞지 않는다.

## 다음 개발 대화에서 먼저 할 일

외부·폰 원격 모드에서는 `DOC-001 → IMP-204S → 실제 AI 사용 조건 논의` 순서로 진행한다. `IMP-204S`는 합성 상황과 평가 계약만 추가하고 앱 화면·라우트·SQLite schema·Expo 설정·프로덕션 조합을 바꾸지 않는다. 승인과 계정이 필요한 `IMP-204C`는 시작하지 않는다.

사용자가 개발 Mac과 Android 폰을 사용할 수 있다고 알리면 `IMP-106`을 재개한다. 최신 `origin/main` SHA에서 `docs/device-validation-checklist.md`의 자동 검증 6개를 Codex가 통과시킨 뒤 필수 실기기 12단계를 합성 이야기로 순서대로 확인한다. 오류가 있으면 같은 작업 안에서 수정·자동 검증·독립 재검수 뒤 영향을 받는 단계와 저장·재실행 핵심 흐름을 새 SHA에서 다시 확인한다. Expo Go는 Mac 개발 서버가 필요한 개발 컨테이너이며 독립 설치형 Inside Me는 DEC-029의 내부 APK 단계에서 만든다.

## 병렬 개발 운영 방식

- 상태: 확정
- 관련 결정: DEC-034
- 상세 역할과 실행 규칙: `docs/development-workflow.md`

주 에이전트가 0단계에서 Expo 기반과 공통 계약을 먼저 고정한다. 이후 첫 기록 흐름을 `앱 핵심·로컬 저장`, `글 기록·감정 확인 UI`, `달력·날짜 상세 UI`의 세 작업으로 병렬 실행하고 주 에이전트가 통합한다.

첫 로컬 MVP에는 독립 서버 백엔드가 없다. 실제 AI 비밀 키와 외부 전송이 필요한 2단계부터 AI 경험 프론트엔드와 AI 중계 서버 백엔드를 분리한다. 역할별 소유 경로, 작업 지시·인계 형식, 통합 순서, 검증과 중단 조건은 개발 워크플로 문서를 원본으로 따른다.

## 개발 전에 남아 있는 핵심 질문

- Q-013: 실제 AI·전사·음성 합성 공급자, 비용과 외부 전송 기준
- Q-012: 외부 사용자 배포 전 위기 대응 흐름
- Q-027: 기록 내보내기 형식과 민감한 임시 파일 정리의 프로토타입 검증
- Q-028: 사용자 우선 감정·욕구 탐색 화면의 정보 밀도와 `한눈에 보기` 방식
- Q-029: 답변됨 — 최신 `origin/main` 한 SHA에서 저녁 누적 실기기 체크리스트 실행

Q-008은 IMP-099에서 대표 감정 중심 DEC-046으로 답변됐다. Q-013은 IMP-203에서 공급자·비용·보존 비교안과 DEC-048 제안을 준비했지만 사용자 선택 전 실제 연결과 외부 전송은 금지한다. Q-012는 개인 로컬 도그푸딩을 막지 않지만 외부 배포 전에는 반드시 답해야 한다. Q-027은 DEC-036의 되돌리기 쉬운 기본안으로 구현하고 합성 데이터 프로토타입 뒤 검증한다. Q-029는 DEC-050으로 답변됐으며 저녁에는 확정된 통합 체크리스트를 따른다.
