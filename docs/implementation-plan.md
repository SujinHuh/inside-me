# Inside Me MVP 구현 시작 계획

- 작성일: 2026-08-19
- 상태: 0단계 시작 준비 완료
- 개발 코드 상태: 아직 프로젝트 스캐폴딩과 앱 코드를 만들지 않음
- 첫 검증 기기: 개발자 본인의 Android 폰
- 첫 실행 방식: Expo Go에서 개발 서버 QR 코드 스캔
- 관련 결정: DEC-020, DEC-021, DEC-022, DEC-025, DEC-027, DEC-028, DEC-029, DEC-030, DEC-034, DEC-035, DEC-036, DEC-037

## 이 문서의 목적

다음 개발 대화에서 이전 맥락을 다시 추측하지 않고 바로 작업을 시작하기 위한 인계 문서다. 구현 단계의 이름뿐 아니라 사용자가 실제로 무엇을 하고 무엇을 확인해야 완료인지 기록한다.

## 코드 구조와 개발 순서의 차이

### 코드는 기능별로 나눈다

- 홈과 기록 시작
- 글 기록
- 자유 음성 기록
- AI 턴 대화
- 감정·욕구 탐색과 사용자 확인
- 로컬 저장
- 월간 달력과 날짜 상세
- 알림
- 외부 AI, 전사와 음성 합성 연결

이렇게 나누면 음성을 고쳐도 달력 코드까지 같이 흔들리지 않고, AI 공급자나 저장 방법을 나중에 바꿀 수 있다.

### 개발은 작은 전체 사용 과정을 하나씩 완성한다

달력 기능 전체를 먼저 만들고, 음성 기능 전체를 따로 만들고, 마지막에 합치지 않는다. 사용자가 앱을 열고 기록을 남긴 뒤 다시 보는 과정이 실제로 작동하는 작은 제품을 먼저 만든다. 이후 입력 방법과 AI 기능을 같은 뼈대에 덧붙인다.

## 0단계 — 프로젝트와 Android 실행 준비

### 할 일

- Q-022와 개발 기준 브랜치를 확정한 뒤 기존 문서를 보존하는 방식으로 TypeScript, React Native, Expo와 Expo Router 프로젝트를 생성한다.
- Node.js, 패키지 관리자, Expo SDK, 생성 템플릿과 공식 패키지 버전을 고정하고 라이선스·데이터 전송 여부를 기록한다.
- 테스트 러너, 로컬 저장 어댑터와 package script를 결정하고 잠금 파일을 만든다.
- 기능별 폴더, 공통 계약, 감정·욕구 어휘 데이터, 가짜 저장소·탐색기, 조합 루트와 플랫폼 연동 경계를 최소한으로 만든다.
- Windows Classic 참고자료를 바탕으로 색상, 테두리, 간격과 글꼴 역할의 첫 디자인 토큰을 만든다.
- 컴퓨터에서 개발 서버를 실행하고 Android 폰의 Expo Go로 QR 코드를 스캔한다.

### 사용자가 확인할 결과

- Android 폰에서 Inside Me 시작 화면이 열린다.
- 앱 이름과 고전 창을 떠올리는 기본 화면이 보인다.
- 코드 한 줄을 바꾸면 폰 화면에 변경이 반영된다.

### 완료 조건

- Play 스토어와 APK 없이 실제 Android 폰에서 실행된다.
- 설치, 개발 실행, 타입 검사와 테스트 명령을 `AGENTS.md`에 실제 명령으로 기록한다.
- 클라이언트 번들에 API 키나 비밀정보가 없다.
- 공통 계약과 가짜 구현 테스트가 통과한 기준 커밋이 있으며, 그 SHA를 실행 상태 원장에 기록한다.
- 사용자의 Android 성공 응답 전에는 `사용자 실기기 검증 대기` 상태를 유지한다.

## 1단계 — 첫 기록 전체 흐름

### 사용자가 하는 일

1. Android 폰에서 Inside Me를 연다.
2. 홈 화면에서 `글로 기록하기`를 누른다.
3. 오늘 있었던 일과 현재 기분을 자유롭게 적는다.
4. `감정 살펴보기`를 누른다.
5. 검색·주제별 필터·세로 스크롤로 감정 어휘를 직접 살펴보고 가까운 표현을 먼저 고르거나 직접 추가한다.
6. 욕구 목록도 주제별로 살펴보고 자신에게 중요했던 항목을 먼저 고른다.
7. 잘 모르겠거나 더 살펴보고 싶으면 `AI와 더 살펴보기`를 선택한다. 초기에는 같은 계약을 쓰는 임시 탐색기가 보조 후보와 근거를 보여 줄 수 있다.
8. 자기 선택과 AI 보조 후보를 비교해 최종 감정, 강도와 욕구를 수정·확정한다.
9. 필요한 경우 한 문장 요약을 확인하고 `오늘 기록 저장`을 누른다.
10. 월간 달력의 오늘 날짜에 표정이 나타난다.
11. 오늘 날짜를 눌러 이야기, 감정, 욕구와 요약을 다시 본다.
12. 앱을 닫고 다시 열어도 기록이 남아 있는지 확인한다.
13. 상세 화면에서 자신이 만든 테스트 기록을 수정하고 다시 저장한다.
14. 합성 기록만 있는 테스트 프로필에서 전체 기록을 파일로 내보내고 내보낸 결과가 열리는지 확인한다.
15. 자신이 만든 테스트 기록의 삭제를 확인하고, 앱을 다시 열어도 돌아오지 않는지 확인한다.

### 개발자가 구현할 최소 기능

- 홈과 글 기록 화면
- 세 입력 방식이 공유할 검색·분류·스크롤 가능한 감정·욕구 자기 탐색 화면과 직접 추가·`아직 모르겠어요` 경로
- 자기 선택, 임시 탐색기 또는 AI 제안과 최종 확정 결과를 분리하는 데이터 계약
- 하루 한 개 기록 저장·수정
- 월간 달력의 대표 표정
- 날짜 상세 조회
- 앱 재시작 후 로컬 기록 복원
- 사용자 확인을 거친 완전 삭제
- 민감정보 안내, 취소·실패 복구와 임시 파일 정리를 포함한 전체 기록 내보내기
- 저장 실패와 빈 입력의 이해 가능한 안내

### 이 단계에서 아직 만들지 않는 것

- 자유 음성 녹음과 전사
- AI와 한 턴씩 음성으로 대화
- AI 질문의 음성 재생
- 취침 전 로컬 알림
- 기기 간 기록 동기화
- PWA 설치와 오프라인 캐시

### 완료 조건

- 사용자가 Android 폰에서 위 15단계를 도움 없이 끝낼 수 있다.
- 같은 날짜에 저장을 반복해 중복 기록이 생기지 않는다.
- 사용자가 먼저 고른 감정·욕구, AI가 제안한 항목과 사용자가 최종 확인한 결과가 데이터에서 구분된다.
- AI 도움을 선택하지 않아도 감정·욕구 확인과 저장 흐름을 끝낼 수 있다.
- 기록 삭제 후 앱을 다시 열어도 삭제된 내용이 돌아오지 않는다.
- 삭제·손상·마이그레이션 자동 테스트는 격리된 namespace 또는 임시 DB의 합성 데이터만 사용한다.
- 전체 내보내기 파일이 기록을 빠뜨리지 않고 다시 읽을 수 있는 형식이다.
- 내보내기는 `schemaVersion`이 있는 UTF-8 JSON을 되돌리기 쉬운 기본안으로 사용하며, 파일명에 사용자 이름·감정·일기 내용을 넣지 않는다.
- 공유 취소·성공·실패 후 앱 cache의 임시 내보내기 파일이 남지 않고 기존 기록은 유지된다.
- 실기기 회귀 검증은 합성 기록만 있는 테스트 프로필에서 수행하며 실제 기록 내보내기는 사용자가 명시적으로 요청할 때만 실행한다.
- 검증 기록에는 내용과 파일 경로 대신 건수, 스키마 버전, 열기 성공 여부와 테스트 파일 삭제 안내만 남긴다.

## 2단계 — 실제 AI 감정 탐색

- 이 단계에 들어가기 전에 사용자 행동, 원자 작업 ID와 완료 조건을 0·1단계 수준으로 구체화한다.
- AI·전사·음성 합성 공급자, 월간 허용 비용과 데이터 보존 정책을 결정한다.
- 서버 런타임·배포 경계·접근 통제와 클라이언트가 서버 코드를 직접 가져오지 않는 경계를 결정한다.
- API 스키마, 오류 의미, 멱등성, 취소·시간 초과, 재시도와 로그 민감정보 제거 계약을 주 에이전트가 먼저 고정한다.
- 사용자 글을 외부 AI로 보낼 때 전송 범위와 이유를 보여준다.
- AI가 한 번에 질문 하나를 하고 감정 후보를 단정하지 않도록 출력 계약과 안전 검사를 적용한다.
- 네트워크 실패 시 작성한 글과 사용자 선택을 잃지 않는다.

## 3단계 — 자유 음성 기록

- 이 단계에 들어가기 전에 사용자 행동, 원자 작업 ID, 실패·취소·재시도와 완료 조건을 구체화한다.
- 한 번 눌러 녹음을 시작하고 다시 눌러 끝낸다.
- 전사 결과를 사용자가 읽고 수정할 수 있게 한다.
- 전사와 분석 성공 후 원본 음성을 삭제한다.
- 글 기록과 같은 감정 확인·저장·달력 흐름을 재사용한다.

## 4단계 — AI와 한 턴씩 음성 대화

- 이 단계에 들어가기 전에 사용자 행동, 원자 작업 ID, 중단·복원·안전 흐름과 완료 조건을 구체화한다.
- 사용자가 한 번 말하면 AI가 짧게 되짚고 질문 하나를 글과 음성으로 제공한다.
- 약 5분, 질문 3~6개를 기본으로 하되 사용자가 일찍 끝내거나 연장할 수 있다.
- 중단된 대화를 이어가거나 안전하게 종료할 수 있다.

## 5단계 — 알림, 실패 복구와 내부 APK

- 이 단계에 들어가기 전에 사용자 행동, 원자 작업 ID, 권한 실패와 완료 조건을 구체화한다.
- 사용자가 정한 취침 전 시간에 Android 로컬 알림을 예약한다.
- 놓친 날을 실패처럼 표현하지 않고 미루기와 건너뛰기를 제공한다.
- 음성·AI·저장 실패에서 기록을 잃지 않는지 검증한다.
- 핵심 흐름이 안정되면 EAS 내부 배포로 APK 설치 링크를 만들고 개발 서버 없이 도그푸딩한다.

## 6단계 — 컴퓨터 웹과 PWA 확장

이 단계에 들어가기 전에 사용자 행동, 원자 작업 ID, 브라우저별 저장·삭제·내보내기와 완료 조건을 구체화한다.

### 공유할 것

- 감정 탐색 규칙과 데이터 형식
- 글 기록, 감정 확인, 달력과 상세 화면의 대부분
- 디자인 토큰과 Windows Classic에서 가져온 시각 언어
- AI 요청·응답 계약과 안전 규칙

### 플랫폼별로 나눌 것

- 마이크 권한과 녹음 파일 형식
- 로컬 저장 구현
- 로컬 알림 또는 웹 알림
- 파일 내보내기와 다운로드
- 화면 크기에 따른 내비게이션

### PWA에서 추가할 것

- 반응형 Android·데스크톱 웹 화면
- 앱 이름, 아이콘과 시작 URL이 들어간 manifest
- 홈 화면 설치 가능 상태
- 오프라인 시작 화면과 지원 범위 안내
- 웹 저장·삭제·내보내기 검증

### 중요한 제한

- Android 앱과 PWA는 모두 기기 로컬에 기록하므로 자동으로 같은 일기를 공유하지 않는다.
- 기기 간 동기화는 별도의 서버·계정·암호화 결정이 필요한 후속 기능이다.
- PWA 때문에 Android 첫 구현을 늦추지 않되 Android 전용 코드를 공통 핵심에 섞지 않는다.
