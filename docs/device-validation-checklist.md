# Inside Me 저녁 실기기 통합 검증 체크리스트

- 작성일: 2026-08-24
- 상태: 확정 — 사용자 확인 완료
- 실행 시점: 사용자가 집에서 개발 Mac과 Android 폰을 함께 사용할 수 있다고 알린 뒤
- 관련 작업: IMP-106
- 관련 결정: DEC-029, DEC-047, DEC-050
- 관련 질문: Q-029

## 목적

외부에서 폰으로 Codex에 접속하는 동안 완료된 작업을 기능 번호마다 따로 다시 실행하지 않는다. 저녁 검증 시작 직전에 최신 `origin/main` SHA 하나를 고정하고, 그 SHA까지 누적된 변경 중 Android 실기기에서만 확인할 수 있는 흐름을 한 번의 순서 있는 회귀 검증으로 확인한다.

순수 비용 계산기처럼 전체 자동 테스트와 독립 검수로 완료된 비화면 로직은 폰에서 같은 계산을 반복하지 않는다. SQLite 지속성, Expo Go 화면, 키보드, 공유 화면, 앱 재실행, 글꼴과 접근성처럼 정적 번들로 증명할 수 없는 항목만 이 문서에 모은다.

## 준비

- [ ] 사용자가 개발 Mac과 Android 폰을 직접 사용할 수 있다고 확인했다.
- [ ] LAN 연결을 쓰면 Mac과 Android 폰이 같은 Wi-Fi에 연결됐다. LAN이 막히면 tunnel로 다시 실행하고 연결 방식을 기준선에 기록한다.
- [ ] Git root와 `origin` URL이 `SujinHuh/inside-me` 저장소를 가리키는지 확인했다.
- [ ] `git switch main`, `git fetch origin main`, `git pull --ff-only origin main` 순서로 동기화했다.
- [ ] 현재 브랜치가 `main`이고 로컬 `HEAD` 전체 SHA가 `origin/main` 전체 SHA와 같으며 작업 트리가 깨끗하다.
- [ ] `nvm use`와 `npm ci`가 통과했다.
- [ ] 실제 감정일기가 아닌 합성 이야기만 사용한다.

권장 합성 이야기: `프로젝트 발표 순서를 기다리며 긴장했지만 준비한 내용을 끝까지 설명했다.` 실제 감정이나 개인정보로 바꾸지 않는다.

## 기기 표시·접근성 확인

아래 항목은 자동 테스트가 대신할 수 없는 실제 Android 표시 확인이다. 설정 변경에 시간이 필요한 항목은 수행 여부와 이유를 남긴다.

- [ ] 감정 표정의 특수문자 눈·입이 네모 상자나 깨진 글자로 보이지 않는다.
- [ ] 작은 화면에서 감정·욕구 목록, 확인 버튼과 오류·안내 문구가 잘리거나 겹치지 않는다.
- [ ] Android 글자 크기를 키워도 핵심 문구와 다음 버튼에 접근할 수 있다.
- [ ] TalkBack에서 버튼·감정 이름·선택 상태·후보 도착 안내를 이해할 수 있다.
- [ ] 색상만으로 선택·오류·기록 유무를 구분하지 않는다.

같은 SHA의 자동 검증 6개와 필수 실기기 12단계가 모두 통과하고 기준 SHA가 기록돼야 IMP-106을 `완료`로 바꾼다. 접근성 항목을 실행하지 못했으면 통과로 체크하지 않고 이유와 후속 작업을 남긴다. 오류 수정 커밋이 생기면 자동 검증을 새 SHA에서 다시 실행하고, 영향을 받는 실기기 단계와 필수 저장·재실행 흐름도 다시 확인한다.
